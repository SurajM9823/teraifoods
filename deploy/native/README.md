# Current server deployment

Preview: http://178.105.139.193/ (HTTP only; avoid real credentials/personal data).
The existing speedassignment.com Nginx vhost and PostgreSQL cluster are retained.
PostgreSQL 16 hosts the separate `teraifoods` database and restricted login role.
Redis and Waitress bind only to loopback. UFW permits inbound TCP 22, 80, 443.

Secrets: `.env.server`, root owned, readable by the app group, excluded from Git.
Web/worker run as the unprivileged `teraifoods` user under systemd with memory
limits, read-only system protection, automatic restart, and startup on boot.
2 GiB persistent swap, swappiness 10. Redis maxmemory 128 MiB with noeviction.

From `/opt/teraifoods`:

```sh
sudo deploy/native/status.sh
sudo journalctl -fu teraifoods-web -u teraifoods-worker
sudo tail -f /var/log/nginx/teraifoods-access.log
sudo .venv/bin/python deploy/native/manage.py createsuperuser
sudo .venv/bin/python deploy/native/manage.py check --deploy
```

Auth requests are intentionally excluded from Nginx access logs to avoid OAuth
code leakage. Email OTP needs working SMTP settings in `.env.server`. Google
sign-in needs its OAuth credentials and a domain callback. Neither is configured.
No admin password is generated by deployment.

Updates: back up first, install requirements.lock into .venv, run migrations and
collectstatic through deploy/native/manage.py, restart teraifoods-web and
teraifoods-worker. Validate Nginx before reload. Keep source/venv root owned.

Daily database backups: /var/backups/teraifoods, 7 days retention, via
teraifoods-backup.timer. Backups are private and remain on this server; copy them
to separate storage for disaster recovery. Run `sudo systemctl start
teraifoods-backup` manually. Test restores in a separate database.

For domain/TLS cutover: configure DNS and a trusted certificate, add a dedicated
Nginx TLS vhost with HTTP redirect, set DJANGO_ALLOWED_HOSTS and
DJANGO_CSRF_TRUSTED_ORIGINS to the real domain/HTTPS origin, and switch
DJANGO_SETTINGS_MODULE to config.settings.production. Verify HTTPS before
setting HSTS. Remove the IP HTTP route when the preview is no longer needed.

An installed kernel update is pending reboot. Schedule that separately because
this server also runs another application.
